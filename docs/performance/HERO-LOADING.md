# إصلاح تحميل وحركة الهيرو — 16 نوفمبر 2026

## الأسباب والإصلاحات

1. `tools/build-performance.mjs`: المعالجة العامة للصور كانت تضيف lazy لصورة الهيرو ذات fetchpriority=high. الصورة الرئيسية أصبحت eager، وباقي الصور خارج الشاشة lazy.
2. `js/hero-b.js`: تغيير اللغة أو جاهزية البيانات كان يعيد إنشاء الصور بـ innerHTML. يتم الاحتفاظ بعنصر الصورة نفسه وتحديث وصفه فقط، فلا يُعاد بدء فك الترميز.
3. `hero-b.css`: مرور الماوس على كارت بصري بلا عناصر تحكم كان يوقف الطفو. أزيل هذا الإيقاف؛ الصور ثابتة في نوعها ولا تتبدل.
4. `performance.css`: تعطيل كل حركات الهيرو على الموبايل استُبدل بطفو خفيف 6px. الدوائر والتوهج والجزيئات المكلفة تبقى مخففة/معطلة هناك.
5. `js/fx.js`: توقف الحركة خارج الشاشة أصبح حالة صريحة، فلا تعتمد الحركة الأولية على وصول callback من IntersectionObserver. تتم إيقافها عند إخفاء التاب واستئنافها عند العودة، مع احترام reduced-motion.
6. بناء CSS كان يستخدم كود المشروع كله لإبقاء كلاس، فكانت صفحات المتجر تحمّل تنسيقات الإدارة والعكس. يستخدم الآن HTML وJS الفعليين لكل صفحة لجميع مصادر CSS، مع الإبقاء التحفظي على الشروط والمحددات المعقدة.
7. أزيل قاعدتان متطابقتان من مصدر performance.css، ويزيل البناء التطابق التام من الحزم. لم تُحذف تعديلات RTL والموبايل المختلفة لمجرد تكرار اسم الكلاس.
8. نُظفت قائمة السكريبتات من إشارات المكتبات القديمة التي كان البناء يتجاهلها أصلًا. لم تُعد GSAP أو Lenis أو WebGL للتحميل.
9. `docs/CODE-MAP.md` يوضح ملكية الملفات وترتيب CSS وما هو مولد. أضيفت أوامر check:hero وcheck:site وcss:audit في package.json.

## النتائج المحلية

قياس واحد لكل عرض، متصفح Chromium على سيرفر static، شبكة 200,000 بايت/ثانية وlatency 100ms، CPU ×4، كاش جديد، reduced-motion. هذه قياسات محلية إرشادية وليست Lighthouse أو ضمانًا لقياس الموقع المنشور.

| المقياس | قبل | بعد |
|---|---:|---:|
| CSS الرئيسية، بدون ضغط النقل | 369,112 B | 252,487 B (-31.6%) |
| CSS الحرج داخل الرئيسية | 132,631 B | 119,403 B (-10%) |
| الموارد المنقولة، موبايل | 784,639 B | 668,836 B |
| الموارد المنقولة، ديسكتوب | 822,021 B | 706,218 B |

| مؤشر المهام الطويلة، موبايل | 418ms | 330ms |

مؤشر المهام الطويلة هو مجموع max(duration - 50ms, 0) خلال فترة القياس؛ ليس Lighthouse TBT. LCP الموبايل متقارب مع هامش تفاوت القياس، فلا ننسب له تحسنًا كبيرًا.

الملفات الخام: `hero-before.json`, `hero-after.json`. صورة الهيرو تستخدم WebP المتجاوب الموجود بالمشروع؛ لم تُغيّر الصورة أو أبعاد الكارت ولم تُحذف الأصول الأصلية.

## التحقق

- 48 مقارنة CSS محسوبة: كل الصفحات الـ16 عند 390/820/1440، دون اختلاف في خصائص التنسيق المقارنة.
- 20 فحص لوظائف الموقع، واختبارات الطلبات والرسائل والمنتجات والتخزين نجحت.
- اختبار مخصص للهيرو: eager/high priority، إعادة استخدام الصور عند تغير اللغة والبيانات، استمرار الحركة تحت الماوس والموبايل، إيقاف/استئناف التاب، تقليل الحركة، صور ظاهرة دون JavaScript، دون أخطاء console.
- اختبار scroll محلي: 95% من الإطارات ≈16.8ms على الموبايل و16.7ms على الديسكتوب؛ طيران صورة السلة يعمل على الديسكتوب.
- لا تعديلات على منطق السلة/المنتجات أو data/* أو style.css. القواعد غير المرتبطة بالصفحة مستبعدة من حزمها؛ قواعد الحالات الديناميكية المحتملة محفوظة ولا ندّعي أن مجرد عدم ظهورها في لقطة يعني أنها غير مستخدمة.

لإعادة القياس من Chrome: افتح الصفحة المنشورة، DevTools → Lighthouse → Navigation → Mobile → Performance. استخدم نافذة خاصة ونفس الجهاز والشبكة قبل/بعد، وقارن وسيط ثلاث جولات. اختبر Desktop بصورة منفصلة. راجع Network للتأكد من أن صورة الهيرو eager وأن الملفات تحمل أسماء hash الجديدة بعد النشر.
