# تحسين أداء متجر AlMumez

تم تعديل النسخة المحلية؛ لم يتم نشرها أو تنفيذ push. تمت مراجعة 15 صفحة فعلية وصفحة تحويل products.html، وملفات الستايل والسكريبتات والصور المرتبطة بها. بيانات المنتجات وstyle.css الأصلي لم تتغير. اختيارات صور الهيرو الموجودة في مساحة العمل وقت بدء المهمة محفوظة.

## التغييرات المنفّذة

- استبدال طبقة fx.js بـ native scrolling وIntersectionObserver وWeb Animations؛ لا GSAP أو Lenis أو ScrollTrigger في الطلبات الفعلية.
- استبدال React Bits/React/WebGL في الصفحات بعناصر HTML وCSS للبراندات والجزيئات الخفيفة، مع الإبقاء على نفس المحتوى والأرقام الحقيقية.
- إيقاف الحركة المستمرة خارج الشاشة وإيقاف الجزيئات والطفو والـ blur على الموبايل، مع احترام reduced-motion والتمرير البرمجي.
- إبقاء طيران الصورة للسلة على الديسكتوب باستخدام transform/opacity؛ تعطيله على الموبايل أو مع reduced-motion.
- ربط scroll/resize بـ passive listeners وإطار rAF واحد، واستبدال قياس الكروت المتكرر بحساب المسافة من عرض الشريط.
- قياس حدود تكبير صورة صفحة المنتج عند دخول المؤشر، ثم تجميع حركة المؤشر في rAF؛ لا قياس هندسي في حلقة mousemove.
- إضافة content-visibility ومساحات تقديرية متجاوبة للأقسام الطويلة والفوتر.
- رسم كروت الرئيسية عند الاقتراب من الشاشة، في عملية innerHTML واحدة لكل شبكة، مع skeleton في HTML ومساحة محجوزة.
- تحديث اكتشاف الكروت بعد الرسم المؤجّل؛ البحث والفلاتر يستطيعان طلب الرسم فورًا عند الحاجة.
- تخفيض تكرار العمل في الترجمة: ترتيب القاموس مرة واحدة، وتخزين النصوص المترجمة، وتجنب إعادة كتابة النص غير المتغير.
- رسم صور الهيرو مسبقًا في HTML وتحميل الصورة الرئيسية مبكرًا؛ النص العربي الأولي يُرسم قبل انتظار حزمة التطبيق، مع دعم الرجوع للإنجليزية.
- توليد صور WebP responsive محلية بـ srcset/sizes، وdecoding=async وأبعاد ثابتة وlazy للصور المناسبة؛ الأصول الأصلية محفوظة.
- معالجة تبديل صورة المعرض وsrcset معًا حتى لا تبقى صورة المنتج السابق أو تتعارض صور IDB المرفوعة.
- تحويل شعار الفوتر من 395,577 إلى 13,358 بايت، مع الحفاظ على الشفافية.
- استبدال خط الأيقونات الكامل بـ subset محلي 18,636 بايت، يدعم الأيقونات المستخدمة وحالة FILL، مع font-display:swap وpreload.
- استضافة Cairo/Tajawal محليًا وإرفاق تراخيص الخطوط؛ لم تعد الصفحات تنتظر Google Fonts خارجيًا.
- وضع Critical CSS لكل صفحة، بما فيه حالات الدرج والقوائم والبحث، وتحميل بقية CSS دون تعطيل الرسم مع noscript fallback.
- تحميل حزمة JavaScript واحدة بـ defer لكل صفحة، بترتيب الاعتمادات الصحيح، وإزالة حزم الكروت من الصفحات المعلوماتية التي لا تعرضها.
- توليد CSS/JS مصغّر وUTF-8 بأسماء hash، وإعادة استخدام الملف نفسه عندما يكون محتواه متطابقًا بين الصفحات.
- تنظيف utilities غير المستخدمة من خرج style.css بناءً على كلاسّات HTML/JS الفعلية، مع الحفاظ على selectors المعقدة وحالات الواجهة؛ لم يتغير ملف style.css الأصلي.
- تجنب إعادة ضبط شريط منتجات الموبايل عند تغيير الكمية أو نص العدّاد، وتحديث حالة الشبكة الفارغة قبل الرسم حتى لا تظهر الكروت متراكمة لحظيًا.
- إبقاء مؤقتات العروض والـ OTP اللازمة للوظائف؛ مؤقتات العرض تتجنب العمل في التاب المخفي، ومراقبة المنتجات أصبحت event-driven بدل polling كل 15 ثانية.

لم يتم إضافة Service Worker: أسعار المنتجات والعروض وتسجيل الدخول تحتاج تجنب كاش صفحات قديمة. أسماء الأصول ذات hash تحقق تغيير الإصدار عند تحديث الملف، مع كاش GitHub Pages الطبيعي. لا توجد مكتبة runtime جديدة، والمكتبات القديمة لم تعد تُطلب؛ مصادرها الأصلية محفوظة للرجوع إليها.

هذه ليست نتيجة Lighthouse أو بيانات مستخدمي الموقع المنشور. القياس بواسطة Chrome/Playwright محليًا على 390 و1440px، CPU ×4، latency 100ms، تنزيل 200,000 بايت/ثانية، كاش جديد وreduced-motion، ومراقبة الأداء لمدة 18 ثانية بعد DOMContentLoaded. Google Fonts الخارجي كان محجوبًا في الاختبارين؛ الخطوط المحلية الجديدة تعمل. الجدول يستخدم وسيط ثلاث جولات لكل عرض، لتقليل تأثير تذبذب الحمل على جهاز الاختبار؛ يُنصح أيضًا بثلاث جولات Lighthouse وأخذ الوسيط.

عمود المهام الطويلة هو مجموع `max(duration - 50ms, 0)` في نافذة الاختبار. هو مؤشر تقريبي لتحسن TBT، وليس TBT الخاص بـ Lighthouse، الذي يستخدم نافذة قياس مختلفة. لا يمكن ضمان نفس النسب على كل جهاز أو شبكة.

حجم الموارد في JSON يجمع الموارد المكتملة فقط ولا يشمل HTML؛ لا يمثل إجمالي البايتات على الشبكة، خصوصًا أن موارد النسخة القديمة الكبيرة قد تبقى قيد التحميل. الاختبار الأصلي استخدم صور مساحة العمل غير المحفوظة في Git وقت البداية، لذلك checkout لنسخة قديمة وحده لا يكرر إعداد الصور نفسه بالضرورة.

## التحقق

- functional.json: 19 حالة تشمل الإنجليزية والعربية، 390/1440px، السلة والكمية والمفضلة واللغة والفلاتر والبحث، وصول المنتجات إلى checkout، وفتح جميع الصفحات بما فيها dashboard وauth؛ لا pageerror.
- css-regression.json: 45 مقارنة للمظهر على 390/820/1440px لكل الصفحات؛ تطابق الأبعاد والمواضع والألوان والخطوط بعد تنظيف CSS. الاختبار ينتظر اكتمال الستايل والحالات المؤقتة، ولا يعامل اختلاف اسم كلاس مؤقت وحده كاختلاف بصري.
- scroll.json: فحص اسكرول فعلي في الوضع العادي، بلا Canvas/WebGL؛ زمن الإطار p95 حوالي 16.8ms محليًا؛ طيران الصورة للديسكتوب يعمل.
- reduced-motion اختُبر في مسارات الوظائف، وصور الهيرو ما زالت للعرض دون روابط.
- products-logic.test.cjs نجح؛ storage-test.cjs نجح في بيئة الذاكرة التجريبية مع الحفاظ على بايتات الصور.
- صور after-hero وafter-catalog محفوظة باللغتين والعرضين بجوار التقرير. before-390.png لقطة full-page من فحص النسخة الأصلية؛ الصور lazy خارج الشاشة قد لا تكون محمّلة في هذه اللقطة.

## إعادة البناء والقياس

1. بعد تعديل CSS أو JS شغّل `npm run build:performance`؛ الصفحات تستخدم الملفات المولّدة في dist، فلا يكفي تعديل المصدر وحده للمعاينة.
2. عند إضافة صور: `node tools/prepare-assets.cjs --images-only` ثم أعد البناء. لتنزيل subset الخطوط وتحديثه: `node tools/prepare-assets.cjs --fonts-only`، ويحتاج اتصالًا بالشبكة.
3. أدوات المتصفح تستخدم Playwright الموجود في البيئة. يمكن تحديد PLAYWRIGHT_PATH وCHROME_PATH عند التشغيل على جهاز آخر؛ لا يحتاج GitHub Pages إلى Node أو Playwright لتشغيل الموقع المنشور.
4. القياس المحلي: `node tools/perf-measure.cjs after`؛ تعيين PERF_RUNS=3 يأخذ ثلاث جولات لكل عرض. لتكرار النسخة الأصلية دون تغيير ملفاتك، عيّن PERF_BASELINE=1 قبل تشغيل `node tools/perf-measure.cjs before`، ثم أعده إلى 0 لقياس after. السيرفر يقدّم المصدر القديم من commit 0b0fe3f مع نفس اختيارات صور الهيرو الموجودة في مساحة العمل. التحقق: `node tools/perf-verify.cjs` و`node tools/perf-scroll.cjs`.

للمقارنة بـ Lighthouse في Chrome DevTools:

1. شغّل النسخة الأصلية والنسخة المحسنة من سيرفر static، بنفس صور الهيرو والبيانات واللغة. احتفظ ببيانات المتجر الفعلية وافتح نافذة Incognito للاختبار.
2. DevTools → Lighthouse → Navigation → Performance، واختر Mobile. اترك Network على No throttling حتى لا يتضاعف الخنق مع محاكاة Lighthouse.
3. استخدم نفس Clear storage وإعدادات المحاكاة وحجم النافذة في النسختين، وأغلق التبويبات والإضافات التي قد تستهلك CPU.
4. نفّذ 3 جولات لكل نسخة، واحفظ HTML/JSON، ثم قارن وسيط LCP وTBT وCLS وطلبات الشبكة؛ كرّر Desktop.
5. في Performance سجّل إعادة التحميل ثم اسكرول لآخر الصفحة، وراجع Long tasks وLayout shifts. في Network جرّب مرة بكاش بارد ومرة ثانية بكاش دافئ.
6. بعد نشر نفس commit على GitHub Pages كرّر القياس على الرابط المنشور؛ الأرقام المحلية ليست بديلًا لقياس CDN والأجهزة الحقيقية.

مرجع أسلوب subset: [Google Material Symbols](https://developers.google.com/fonts/docs/material_symbols). تراخيص الخطوط في assets/fonts/licenses. كل الصور المستخدمة تُقدّم محليًا، ولم يتم حذف الأصول الأصلية أو تغيير بيانات المنتجات.

كانت خريطة الصور في js/hero-b.js والصورة f1.png تحملان تغييرات سابقة غير محفوظة في Git. تم الحفاظ عليها في مساحة العمل، وبُنيت نسخ العرض المحسنة على اختيارات الصور الحالية. تظل هذه الاختيارات الأصلية خارج commit الأداء؛ التغييرات المحفوظة في ملف الهيرو تخص تحميل الصور فقط.
